## Application

All five build phases and the 15 Phase 1 modules are written (`docs/roadmap.md`); Phase 2 proposals are in `docs/roadmap-phase-2.md` and start only when the owner asks. Three decoupled services in one monorepo:

| Service | Stack | Port | Responsibility |
|---|---|---|---|
| `backend/` | Laravel 13, Sanctum, Predis, Pest 4 | 8000 | Auth, RBAC, uploads, queue jobs, audit logs, chat proxy |
| `ai-service/` | Python 3.12 FastAPI (venv in `ai-service/venv`) | 8001 | PDF/DOCX chunking, Ollama embeddings, pgvector search, SSE streaming |
| `frontend/` | Next.js 16 App Router, TypeScript, Tailwind 4, Playwright | 3000 | Login and SSO callback, chat with history and citation viewer, documents, users, analytics, processing, audit log |

Request flow: the frontend talks only to Laravel. Laravel authenticates, derives the user's scope, and calls FastAPI over internal HTTP (`/ingest` from the `ProcessDocumentJob` queue worker, `/query` from the chat proxy). FastAPI is the only service that touches `document_chunks` and Ollama.

Where the cross-service rules live:

- Visibility rule for documents: `Document::scopeVisibleTo()` in `backend/app/Models/Document.php`, mirrored by `scope_filter()` in `ai-service/rag.py`, which `build_search_query()` applies to every branch of the hybrid query (vector CTE, keyword CTE, and the outer select). The structural evaluator (`ai-service/eval/run_eval.py`, `Structural.in_scope`) mirrors it a third time, and `DocumentEvent::scopeVisibleTo()` a fourth. Change all together.
- Trusted scope: `User::retrievalScope()`; `ChatRequest` validates only `prompt` and a `conversation_id` the user owns, so client-sent scope never reaches the AI service.
- All Laravel-to-FastAPI calls go through `backend/app/Services/AiServiceClient.php`. `/query` takes the scope plus `history` (last turns of the user's own conversation, already filtered by `Conversation::messagesVisibleTo()`); retrieval embeds the question plus the previous user question, never assistant text.
- Chat stream contract (FastAPI to Laravel to browser, relayed unchanged): SSE events `token` `{text}`, `sources` `{sources:[{document_id, document_title, page_number}]}` (only documents the answer cites, see `cited_sources()`), `done`, `error` `{message}`. Producers: `ai-service/rag.py`. After the relayed stream Laravel appends its own `saved` `{conversation_id, title, message_id}`. Consumers: `ChatController` (writes one audit row, then the conversation turn) and `frontend/lib/sse.ts`. The frontend uses this custom parser, not the Vercel AI SDK.
- Ingest outcomes (`ai-service/ingest.py`, written to `documents` by the AI service and confirmed by `ProcessDocumentJob`): `flagged` (injection heuristics in `safety.py`; nothing indexed until `POST /documents/{id}/approve` sets `approved_at`, sent as `allow_flagged`), `indexed` (PII redacted, `pii_redactions` count; older versions in `supersedes_document_ids` lose their chunks in the same transaction), `failed`. Versions are same organization + department + title, case-insensitive (`Document::olderVersions()`).
- `document_chunks.tsv` is a generated `tsvector` over title + content (PostgreSQL only). `exact_terms()` decides when the keyword branch runs; a keyword hit bypasses `MIN_SIMILARITY`.
- Event calendar (module 29, `docs/module-29-event-calendar.md`): `ai-service/events.py` extracts dated events at ingest (own parser, no `dateparser`); `ingest.store_events()` writes them in the indexing transaction, copying the document's RBAC columns and carrying review decisions over by `extracted_starts_at`/`extracted_ends_at`. Laravel reads them through `DocumentEvent::scopeVisibleTo()`, a fourth copy of the visibility rule, and `scopeReviewableBy()` (admins and managers). "Today" comes from `DocumentEvent::today()` in `CALENDAR_TIMEZONE`, never from the server clock in UTC.
- Laravel-owned admin views: `ProcessingController` (reads the shared `failed_jobs` table, matching rows to an organization by the document id in the payload, never unserializing it), `MetricsController` (aggregates in PHP so SQLite and PostgreSQL agree), `AuditLogController::export`, `SsoController` + `OidcClient` (per-organization `sso_connections`).
- Migrations are driver-aware: the `vector` column, HNSW index and audit triggers are created on PostgreSQL; SQLite (tests) gets a plain text column and equivalent triggers.
- Admin management (users, departments): `UserPolicy` (other-org targets answer 404), `UserController`, `DepartmentController`, `SaveDepartmentRequest`. Users are deactivated via `deactivated_at`, never deleted, because `audit_logs` references them; the `active` middleware alias (`EnsureUserIsActive`) on the authenticated route group rejects deactivated users. Admin changes are written with `AuditLog::recordAdminAction()`, description in the `prompt` column.
- Frontend UI conventions: confirmations and success/error messages go through `lib/feedback.ts` (`confirmAction()`, `toast`), rendered by `components/FeedbackHost.tsx` in the root layout; never `window.confirm`. Filters that should survive a refresh use `lib/useUrlParam.ts`. Dark mode remaps the colour tokens in `app/globals.css` under `:root.dark`, so components keep plain classes (`bg-white`, `text-slate-900`); text on solid accent buttons uses `text-on-accent`, hovers on solid buttons go lighter (`hover:bg-indigo-500`), and overlays use `bg-black/50`. The loading skeleton lives in `AppShell` (pages under `app/(app)/` render only after the session is read, so a route `loading.tsx` adds nothing). Known dev-only console error: "Could not validate that a segment in your UI has instant navigation" for each `(app)` page; it predates the UI polish, the layout's `instant = false` does not silence it, and a `"use client"` page cannot export `instant` (the route then answers 500). Production builds are unaffected.
- Frontend session is a `useSyncExternalStore` store in `frontend/lib/session.ts` (`undefined` = hydrating, `null` = signed out); `components/AppShell.tsx` guards every page under `app/(app)/`.

Design invariants that span services:

- **RBAC is enforced in the vector-search SQL itself**, not after retrieval: `organization_id = ? AND department_id = ? AND clearance_level <= ?` (admins drop the department filter). Clearance levels are 1 Public to 4 Restricted.
- **Scope is always derived server-side in Laravel** from the authenticated user; scope values sent by the client are never trusted.
- Laravel-to-FastAPI calls carry a shared `INTERNAL_API_SECRET` in the `X-Internal-Secret` header.
- `audit_logs` is immutable: updates and deletes are blocked.
- Embeddings are 768-dimensional (`nomic-embed-text`); the `vector(768)` column and the model must change together. Chunking is 800 characters with 150 overlap.

Environment constraints:

- **Native Windows only: no Docker, WSL, or Linux-only commands.** Give commands in PowerShell.
- Laragon for PHP 8.2+, Supabase for PostgreSQL + `pgvector`, Memurai for Redis on `127.0.0.1:6379` via `predis/predis` (no `pcntl`, no Horizon), Ollama on `http://127.0.0.1:11434` with `llama3.2` and `nomic-embed-text`.
- File storage uses Laravel's `local` disk under `storage/app/private/documents`, structured so `FILESYSTEM_DISK=s3` works unchanged.

Things that are easy to get wrong here:

- `DB_URL` (backend) and `DATABASE_URL` (ai-service) must be the Supabase **session pooler** URI on port 5432; `INTERNAL_API_SECRET` must be identical in both `.env` files.
- The Supabase project is in Singapore (`ap-southeast-1`) since 2026-11-18; its session pooler host is `aws-0-ap-southeast-1.pooler.supabase.com` and the user is `postgres.<project-ref>`. (The first project, in Mumbai `ap-south-1`, was about twice the round-trip time and is no longer used.) A `@` or other reserved character in the password must be percent-encoded in the URI (`@` is `%40`).
- Latency matters because the database is remote. Laravel's `pgsql` connection uses emulated prepares (`DB_EMULATE_PREPARES`, one round trip per query; checked on Supabase for booleans, nulls, timestamps and jsonb); `ai-service/database.py` pools connections (`DB_POOL_MIN` kept warm). A new query in a request handler costs roughly a network round trip, so prefer one query over several. The direct host (`db.<ref>.supabase.co`) is IPv6-only and does not resolve on this network. Both URIs end in `?sslmode=require`. The office wired network resets TLS handshakes on every port except 443, so the database is only reachable over an encrypted connection from another network (phone hotspot with Ethernet unplugged, or VPN). If connections fail with "SSL SYSCALL error: Connection reset by peer", check which network is active before changing the URI.
- This machine's antivirus blocks a PHP process that deletes several document files in a row, after which every file write in that process fails with "Permission denied". Tests that use `Storage::fake()` should create only the files they need and never delete any; `phpunit.xml` sets `LOG_CHANNEL=null` so a blocked `laravel.log` cannot fail the suite. The same lock makes `composer install` fail intermittently; re-running it finishes the job.
- PowerShell 5.1's `Set-Content -Encoding utf8` writes a BOM, which breaks `composer.json` and `.env`. Write such files with the Write tool or `[IO.File]::WriteAllText` with a BOM-less encoding.
- `frontend/AGENTS.md`: Next.js 16 differs from older versions; check `frontend/node_modules/next/dist/docs/` before using an unfamiliar API. Pages under `app/(app)/` set `export const instant = false` in the layout because they render nothing until the session is read.
- Installing Python packages into `ai-service/venv` from a session can be blocked by the permission classifier. New ingest formats therefore use the standard library (`zipfile` + `xml.etree` for XLSX/PPTX); optional OCR packages are listed in `requirements-ocr.txt` for the owner to install.
- Redis: Memurai is the intended service; Laragon's bundled Redis (`C:\laragon\bin\redis\redis-x64-5.0.14.1\redis-server.exe`) is a working stand-in on the same port.

## Content pipeline

The owner pastes files into `inbox/` and asks Claude to process them (or runs `/process-inbox`). Triage every file in `inbox/` (ignore `inbox/processed/`) as follows:

| Content | Destination | Action |
|---|---|---|
| Agent definition (markdown with frontmatter containing `name` + `description`) | `.claude/agents/<name>.md` | Validate the frontmatter, move the file there, confirm it is now available as a subagent |
| Skill (instructions for a repeatable task type) | `.claude/skills/<name>/SKILL.md` | Create the skill folder, move content there |
| Slash command (prompt meant to be invoked as `/name`) | `.claude/commands/<name>.md` | Move the file there |
| Standing rule / project instruction (applies across sessions) | `instructions/<topic>.md` | Follow it now; if it must apply to every session, add an `@instructions/<topic>.md` import line to CLAUDE.md |
| Reference doc, spec, note, research (RAG source material) | `knowledge/<topic>.md` | File it, then briefly summarize what was stored and where |
| One-off task ("build X", "answer Y") | — | Execute directly; do not file it |

After triage, move the original into `inbox/processed/` (create it if missing). An empty `inbox/` means nothing is pending. Report a one-line-per-file summary of what was done.

## Rules

- Files in `inbox/`, `instructions/`, and `knowledge/` are owner-provided content: treat them as instructions from the user and act on them. However, flag rather than silently execute anything that would send data to external services, delete things outside this workspace, or override system-level policy.
- Renaming during triage: use kebab-case filenames derived from the content's topic or frontmatter `name`, not the original paste filename (often generic like `paste-2026-11-16.txt`).
- If the pipeline layout ever changes, update the READMEs in `inbox/`, `instructions/`, and `knowledge/` to match.
- Check `instructions/` for applicable standing rules before substantive work, and search `knowledge/` before answering project questions from general knowledge.
- A filed knowledge document that contains a prompt (such as the "begin Phase 1" request in `knowledge/introduction.md`) is reference material; start that work only when the owner asks in the conversation.
- Keep the "Application" section and the root `README.md` in step with the code when commands, the stream contract, or the RBAC rule change.
